Setup Guide

Quick start: keep Built-in Sensors enabled, optionally enable Enhanced Hardware Sensors, then fine-tune with Sensor Selection and Overlay Settings.
Recommended setup order: launch SiR -> verify built-in groups -> optionally enable enhanced or compatibility sources -> tune overlay/web monitor -> save a backup export.
1) Choose Sensor Providers
  • Built-in Sensors provides CPU load, memory, drives, and network telemetry without another monitoring app.
  • Enhanced Hardware Sensors adds supported GPU, temperature, clock, power, voltage, and fan readings.
  • In Settings → Monitoring → Sensor Sources, enable compatibility providers only when you need their additional readings.
  • Optional provider apps must be running only when their source is enabled.
  • If multiple providers expose similar sensors, keep one preferred source active first to avoid duplicate/noisy categories while building your layout.
  • After initial setup, only enable additional providers when you specifically need their unique metrics.
2) Optional Provider Details
  • AIDA64: File → Preferences → External Applications → enable Shared Memory.
  • HWiNFO/LHM: enable shared-memory sensor output in their settings.
  • Built-in Sensors: automatically detects AMD, NVIDIA, and Intel adapters for native FPS and Frame Time through the bundled Windows presentation-event collector.
  • RTSS/MSI: remains available as an optional compatibility source for FPS and shared-memory telemetry.
  • Enhanced access: availability depends on hardware, firmware, Windows security settings, and permissions.
  • If values look stale: restart the provider first, then restart SiR so shared-memory mappings are refreshed in order.
  • When using startup automation, ensure provider apps start before SiR (or use SiR startup delay) so mappings are available at first poll.
  • After changing provider sensor configuration, wait a few refresh cycles before troubleshooting to allow cache/history to repopulate.
3) Build Your Layout
  • Use Visible Sensors to show/hide whole groups (FPS, CPU, GPU, Memory, PSU, Fans, Network, Ping, Drives, App, Other).
  • Use Sensor Selection for per-sensor visibility, overlay inclusion, and drag-to-reorder.
  • Use Summary Mode for a compact overall snapshot.
  • Right-click a sensor row (or use the rename button) to apply a custom display name without changing source telemetry.
  • Use the reset button beside Rename to restore only that sensor's original name.
  • Start with only critical groups (CPU/GPU/FPS/Temps), then add extra sensors after baseline readability is good.
  • Use custom names to shorten long provider labels so web/overlay rows remain clean and readable in tight layouts.
4) Overlay Setup
  • Enable overlay in Appearance → On-Screen Overlay.
  • Configure style, position, monitor, font size slider, spacing, unit scale, colors, and background opacity.
  • Set a global Toggle Hotkey to quickly show/hide overlay in game or desktop use.
  • Use Per-Category Line Limits in grouped-line style to keep noisy groups readable during gameplay.
  • If overlay seems too dense, reduce groups first, then tune line limits and font scale instead of shrinking everything globally.
  • If overlay position resets unexpectedly, disable custom drag placement and re-apply a fixed corner position.
5) Web Monitor & Sharing
  • Enable Web Monitor in Connectivity, then apply host/port settings.
  • Use 127.0.0.1 for local-only access. Use 0.0.0.0 to listen on all interfaces (LAN), and note this can also allow WAN/public access if firewall rules, router port forwarding, or cloud/public networking expose the port.
  • Open the provided URL from another device on the same network if LAN sharing is enabled.
  • If remote devices cannot connect, verify Windows Firewall inbound rules for the selected port and confirm both devices are on the same subnet.
  • If browser view works locally but not on LAN, test ping between devices first, then confirm port accessibility using the host device IP + configured port.
  • Avoid exposing web monitor to public internet unless you intentionally control access at firewall/router level.
6) Update & Startup Controls
  • Use Auto-check for updates on startup to automatically check GitHub releases each launch.
  • Startup Delay is usually unnecessary for built-in sensors, but can help optional provider apps finish loading after login.
  • If in-app downloading is unavailable for a release, use Open Latest Release as the fallback path.
  • For fast logins, start with 3-5 seconds delay and only raise it if providers initialize slowly.
  • After changing startup/tray behavior, perform one full restart test to confirm expected launch/minimize behavior.
7) Troubleshooting Missing/Stale Sensors
  • Confirm Built-in Sensors is enabled in SiR.
  • Enable Enhanced Hardware Sensors for supported temperatures, clocks, power, voltage, and fans.
  • For optional sources, re-check provider shared-memory options and restart the provider app.
  • For native FPS/Frame Time issues, run SiR as administrator and make sure the game is actively presenting frames; if using the optional RTSS source, verify RTSS/MSI is also running.
  • If needed, restart SiR after provider configuration changes.
  • If a single group is empty, verify that group is enabled in Visible Sensors and not filtered out in Sensor Selection.
  • If only Ping looks wrong, verify the configured Ping Host and wait for several samples before judging min/avg/max.
  • If optional-provider data appears frozen, restore the app and confirm that provider is still running.
  • If a recent import changed behavior unexpectedly, restore your previous exported settings backup.
8) Final Validation Checklist
  • Built-in Sensors is enabled and CPU/RAM values update without another monitoring app.
  • CPU/GPU/FPS/Ping groups show changing values (not static zeros).
  • Overlay toggle and hotkey both work as expected.
  • Web monitor opens from the app and displays live updates.
  • Startup/tray/update preferences behave correctly after a restart.
  • Settings exported successfully as a recovery point.

Enable Enhanced Hardware Sensors?

Enhanced Hardware Sensors reads low-level temperatures, fan speeds, clocks, power, and other hardware data.

Where required, SiR will install or update its bundled PawnIO hardware-access driver. This driver is needed for Intel CPU package power and other protected low-level readings; no separate monitoring application is installed.

SiR System Monitor will also enable Launch app as administrator under Startup & Tray, then close and restart with administrator privileges. Windows will show a User Account Control prompt now and on future launches.
